EnemyChase shot sound guide
===========================

Goal
----
Player child object has the gun/muzzle, but EnemyChase needs to react to the shot.
Do not make EnemyChase search inside the Player hierarchy every frame.
The gun already knows the shot position, so the gun should announce "a shot happened here".
EnemyChase should listen to that announcement and decide whether this enemy is close enough to investigate.


Recommended flow
----------------
1. AssultRifle fires.
2. AssultRifle raises an event with the sound position.
3. Every EnemyChase receives that event.
4. Each EnemyChase checks distance from itself to the sound position.
5. If inside hearing range, set DoFind = true and move to the sound position.
6. When the enemy reaches that position:
   - If EnemyFindArea detects Player exactly, continue into detect/attack/chase logic.
   - If only a hidden/sensed Player exists, stay suspicious or search.
   - If nothing is found, DoFind = false and return to idle/patrol/original position.


Why event is better here
------------------------
The sound source is inside Player's child hierarchy, but EnemyChase should not need to know that.
If EnemyChase directly stores PlayerGun or Muzzle references, every enemy becomes dependent on the Player prefab structure.
With an event, AssultRifle can send _muzzle.position or transform.root.position, and enemies only care about the Vector3.


AssultRifle side example
------------------------
Add this near the fields:

    public static event System.Action<Vector3> OnShotSound;

Then inside Attack(), after the shot is confirmed, call:

    OnShotSound?.Invoke(_muzzle.position);

Current Attack() has an early return here:

    if(!Physics.Raycast(_muzzle.position, muzzleDir, out RaycastHit muzzleHit, AttackRange)) { return; }

If the event is placed after that line, enemies will not hear shots that do not hit anything.
Usually gun sound should happen even if the bullet hits nothing, so place the event after muzzle flash / trail starts,
before the second raycast can return.

Example position:

    StartCoroutine(SpawnBulletTrail(targetPoint));

    GameObject flash = Instantiate(_muzzleFlash, _muzzle.position, _muzzle.rotation);
    StartCoroutine(FlashEffectDestoryRoutine(flash));

    OnShotSound?.Invoke(_muzzle.position);


EnemyChase side example
-----------------------
EnemyChase should subscribe/unsubscribe:

    [SerializeField] float _hearingRange = 25f;
    [SerializeField] UnityEngine.AI.NavMeshAgent _agent;

    Vector3 _soundPosition;
    bool _hasSoundPosition;

    void OnEnable()
    {
        AssultRifle.OnShotSound += HandleShotSound;
    }

    void OnDisable()
    {
        AssultRifle.OnShotSound -= HandleShotSound;
    }

    void HandleShotSound(Vector3 soundPosition)
    {
        float distance = Vector3.Distance(transform.position, soundPosition);
        if (distance > _hearingRange)
        {
            return;
        }

        _soundPosition = soundPosition;
        _hasSoundPosition = true;
        DoFind = true;

        EnemyMoveToSoundPosition();
    }

    void EnemyMoveToSoundPosition()
    {
        if (!_hasSoundPosition || _agent == null || !_agent.enabled || !_agent.isOnNavMesh)
        {
            return;
        }

        _agent.SetDestination(_soundPosition);
    }


Important DoFind detail
-----------------------
Your comment says:

    If enemy reaches the sound position and nothing is in overlap sphere, DoFind = false.
    If Player is there, DoFind = true.
    If Player is hidden, DoFind = false.

That direction is mostly right, but split "sensed" and "detected" clearly:

    IsDetectedPlayer == true
        Enemy has exact target. It can face/attack/chase.

    IsSensePlayer == true
        Enemy only knows something is nearby. It should investigate/search, not attack immediately.

    PlayerStealth.IsHidden == true
        Enemy should not get exact target from vision. It may still move to the sound position.

So DoFind should mean "enemy is investigating/searching", not "enemy can attack Player".
For exact Player tracking, use IsDetectedPlayer and DetectedTarget.


Suggested state meaning
-----------------------
DoFind = true:
    Enemy is moving to or searching around the last suspicious position.

DoFind = false:
    Enemy has no current suspicious position and can return to idle/patrol.

DetectedTarget != null:
    Enemy has exact Player transform and can chase/attack.


Small warning
-------------
If many enemies subscribe to AssultRifle.OnShotSound, all of them will receive every shot.
That is fine, because each enemy filters by _hearingRange.
If later there are multiple weapon types, move the event to a shared PlayerNoiseEmitter or NoiseSystem instead of keeping it only on AssultRifle.
